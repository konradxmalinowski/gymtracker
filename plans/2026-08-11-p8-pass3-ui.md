## Key facts confirmed before writing code

- `exercise.body_part` (-> `ExerciseListItem.bodyPart`, already on
  `SessionExercise.exercise`) is derived at catalog-build time from the exercise's
  first primary muscle's `muscle.body_part` (`scripts/build-catalog.ts`'s
  `MUSCLE_TO_BODY_PART`) - it IS the value `ProgressionAdvisor.primaryMuscleBodyPart`
  wants. No new query/column needed; `SessionExercise.exercise.bodyPart` and
  `.equipmentSlug` are sufient inputs, already flowing through `ActiveWorkoutScreen`.
- This branch (`feat/p8-progressive-overload`) does not contain P7's rest-timer
  implementation (only the empty `.gitkeep` skeleton) - `app/profile/settings/
  timers.tsx` does not exist here. `UnitsSettingsScreen.tsx` is the real structural
  precedent for `ProgressionSettingsScreen`.
- `activeWorkoutStore` rule 2/5 (selectors only, synchronous store update + repo write
  pairing) governs the `newPRs` wiring - added as a plain `latestPR: PersonalRecord[]
  | null` field + `setLatestPR`/`clearLatestPR` actions, written from
  `useCompleteSet`'s existing `.then()` continuation (async, after the hot path).
